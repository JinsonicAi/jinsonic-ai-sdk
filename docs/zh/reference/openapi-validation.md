## 实机实际覆盖

- Python、Node、curl 使用设备网页账号领取 Client 凭据，然后沿用原 `auth/token` 和业务 API。
- 错误输入、只读权限、私有接口隔离、密钥只返回一次、认证限流；每台复用 Token 连续查询 40 次。
- 专用测试账号改密后旧 Secret、Token 和已有 WSS 失效；密码改回原值不复活，权限变化/删除账号同样失效。
- 使用隔离的真实 H.264 RTSP 源，创建、修改、启停、查询媒体输出、删除本次新任务；验证节点 metrics、幂等写入和 revision 冲突。
- HTTP 事件收取/继续读取，WSS ready、真实任务事件和正常取消订阅。
- 业务回归期间应用进程未变化；原有账号、密码、权限和任务 revision 保持不变；测试任务/账号已清理，测试 Client 已禁用并保留审计记录。
- 远程维护服务未重启，设备 boot_id 未变；安装使用 SSH + 正常 dpkg，不是 OTA/整机刷写测试。

改密测试通过专用账号的真实 SQLite 更新触发生产撤销逻辑，**没有修改管理员密码，也不等于网页改密 UI 已验收**。HTTP 登录页返回 200 也不能当作交互式网页登录通过。

## 本轮修复后的故障处理

已补齐 TaskManager/JDK 运行库配套与最终包动态链接检查，修正节点 metrics 的链接声明。WSS 示例会处理没有请求 ID 的错误帧；临时 42901/50301 只对安全读/轮询/ACK 做有限退避。服务端临时认证不可用不会被当成真实断连而误删订阅，实际凭据撤销仍拒绝访问。

这些专项修复和通过结果不能替代长期并发、客户业务事务和可靠事件投递设计。

## 必须保留的限制

!!! warning "历史证书与客户直连"
    测试板历史 CA 缺少 Key Usage，服务端 SAN 不含实际 LAN IP。实机验证经受信任 SSH 转发访问真实设备 HTTPS/WSS，匹配 localhost SAN，证书链和主机名校验始终开启；没有使用 `-k`。这不能证明裸 LAN IP 配合旧证书可直接用于客户生产。上线前须提供合规 CA、匹配实际域名/IP 的服务端证书及可靠授时。Python 3.13+ 默认严格验证的旧 CA 兼容问题尚未通过自动证书迁移解决。

AX 测试板安装后的一次新 SSH 核验达到 60 秒超时；安装日志确认 dpkg 成功，随后独立检查、完整 API 回归及运行文件核验通过。超时原因尚未确认，保留为启动阶段响应性风险，不能归因为已证明的 CPU/eMMC 问题，也不能写成“安装全程无异常”。

本轮未覆盖网页交互式登录/改密、网页上传/取消升级、OTA 自安装、固件、重启/掉电/回滚；未逐帧检查画质/OSD/报警图，也未验收全部模型、可选 API、客户摄像机、长时间断网或极限多任务负载。
